- [x] **D2 — Layout model → EXPLICIT SPLIT-TREE (Strategy B).** Build a true Blender area split-tree as a new *optional* top-level `out.layout` descriptor; when absent (all old sitches) fall back to today's fractional rects unchanged. See [LAYOUT-MODEL.md](LAYOUT-MODEL.md).

Key finding: Blender headers are *lighter than* the main menu, not absolute-light.
- [x] **D4 — Surfaced controls: replace vs mirror → MIRROR (individual items).** `src/MenuMirror.js` (`registerMirrorSource`/`mirrorMenuItem`/`clearMenuMirrors`/`syncMirroredSource`): mirror a single lil-gui controller into another menu, bound to the same `object[property]` so value/options/onChange stay in sync; order-independent (producer registers by key, consumer requests by key, second one wires up); `clearMenuMirrors` on sitch teardown, **keeping `.perm()` sources** (they survive `menuBar.destroy(false)`, so their registrations must too). Twin kinds are read from the CSS class lil-gui stamps on the controller (`number`/`color`/`option`/…) rather than `constructor.name`, which minification renames. Name, tooltip, visibility, option list and slider range all propagate source→twin; requests are remembered so a source that is destroyed and re-created under the same key (video Rotation, on every video load) **rebuilds** its row instead of stacking a second one. First use: the Settings "AI Model" dropdown in the Assistant header; now the backbone of 4.2 below. (Distinct from `CustomManagerMirror`, which clones whole folders into windows.)

## Phase 2 — Snapped tiling via split-tree (first focus) — Strategy B, see [LAYOUT-MODEL.md](LAYOUT-MODEL.md)
- [x] **2.1 — split-tree model + geometry walk DONE (2026-06-22).** New `src/CLayoutManager.js` (`LayoutMan` singleton): `LayoutNode` tree (`split{dir,sizes,children}` / `leaf{viewId}`), geometry walk from the Content rect (`ViewMan.{leftPx,topPx,widthPx,heightPx}`) → per-leaf px rect, reserving `LAYOUT_DIVIDER_PX=4` between adjacent tiles; lazy `_recomputeIfNeeded` (re-walks only when the container rect changes or dirtied); `removeLeaf`/`_collapse` (single-child split collapses), `leafViewIds`, `serialize`. Exposed as `window.LayoutMan`.
- [x] **2.2 — updateWH() hook DONE (2026-06-22).** `CNodeView.applyLayoutRect()` (called at the top of `updateWH`, parallel to `updateDockedWH`): leaf-in-tree → take the tile rect + mirror it back into the legacy `left/top/width/height` fractions (keeps serialization consistent + gives a sane floating rect on later detach); else legacy path **unchanged**. Overlays/`relativeTo` children are never leaves. Verified live (MCP): canonical Layout Test tree → main left 958px | right column 962px with the 4px seams reserved.
- [x] **2.3 — divider drag (coupled resize) + INTERACTIVE seams DONE (2026-06-22).** `LayoutMan.dragDivider(divider, dxPx, dyPx)` adjusts the two adjacent `sizes` of one split (sum preserved, neither tile below `MIN_TILE_FRAC=0.05`); `dividerAt(px,py,tol)` for hit-testing. **Interactive:** `_syncDividerDOM` builds a transparent grab strip (`DIVIDER_GRAB_PX=10`, col-/row-resize cursor) over each seam in a `z=55` layer in the Content container; pointer-drag (`_onDividerPointerDown`, snapshots sizes at start → absolute mapping, document move/up/cancel) resizes live. Elements reused across recomputes (rebuilt only on seam-count change) so a drag isn't destroyed mid-walk. **Acceptance test committed** (`split-tree-layouttest.scenario.mjs`: value baseline + coupling assert): vertical seam resizes main + the whole right column (inner split untouched); horizontal seam resizes video/look only. Verified live (MCP pointer-event drag → views follow + divider DOM repositions) + headless.
- [x] **2.4 — `out.layout` serialization DONE (2026-06-22).** `getCustomSitchString` writes `out.layout = LayoutMan.serialize()` (view ids + seam sizes; null when not tiled). Deserialize stashes `Sit.layout`; end of `setupFunctions` does `Sit.layout ? setLayout(Sit.layout) : autoTileIfSnapped()`. `setLayout` prunes leaves whose view doesn't exist (`_pruneMissingLeaves`) so a stale saved tree can't leave phantom tiles. Each leaf's fractions still serialize per-view ⇒ an older build that ignores `out.layout` renders ~the same rects (forward-compatible). Verified: saved string carries the dragged seam sizes; clear→restore roundtrip is exact (scenario assert). Honoured outside regression mode only (keeps baselines deterministic).
- [x] **2.5 — detach + RE-DOCK + RESET DONE (2026-06-22).** Detach: dragging a tiled view's header past `HEADER_DRAG_DETACH_THRESHOLD=30px` pops it out (`_applyDragMove` → `LayoutMan.removeLeaf`), restores its edge-resize handles, floats it; the split **renormalises** (`removeLeaf`/`_collapse`; lone-view collapse drops tiling). **Re-dock:** dropping a floating view over a tile (drag-end, `onViewDragEnd` → `LayoutMan.dockViewAt`) **splits that tile** to re-insert it — Blender-style, axis+side from the drop quadrant (`_leafNodeAt`/`_findLeafNode`). **Reset Layout** (View menu, `LayoutMan.resetLayout`) forces all visible views back into a clean grid **ignoring positions** (recovers from any overlap/stuck state; mainView left, rest stacked right). Verified live + scenario asserts (detach→collapse, reset→rebuild, redock→split). _Later: join; reconcile `scriptZ`/`alwaysOnTop` overlay HUDs._
- [x] **2.6 — rect→tree reconstruction + AUTO-TILE-ON-LOAD DONE (2026-06-22); hidden-leaf still PENDING.** `LayoutMan.tileFromViews()` reads the visible top-level views' fractional rects and recovers a tree by recursive **guillotine cuts** (`buildGuillotineTree`/`findCut`/`makeSplit`). **Auto-on (Mick's call):** `autoTileIfSnapped()` runs at the end of `setupFunctions` (both load paths) and tiles ONLY when the views already form a **complete snapped grid** (`_isSnappedTiling`: sum-of-areas ≈ 1 + full bounding box) AND none are **aspect-locked** (negative w/h → bail). **Edge-to-edge** (`LAYOUT_DIVIDER_PX=0`) so an auto-tiled snapped layout has IDENTICAL geometry — purely adds coupled seams. Skipped under `?regression=1` (keeps legacy baselines deterministic). Verified live: the Layout Test sitch auto-tiles to `v[mainView,h[video,lookView]]`; **gofast (aspect-locked look/video) correctly does NOT tile**. Also a **View ▸ Tile Layout** toggle for manual control. STILL OPEN: hidden-leaf behaviour (collapse-and-redistribute vs reserve), and **Q-detach (2.5) so a tiled view can be pulled out** (right now a tiled view's header-drag snaps back + its own resize handles are hidden — seam is the only resize).

## Phase 4 — Surface common actions as viewport controls
- [ ] **4.1** Shared **playbar/scrubber** (biggest win): wire to `KeyBoardHandler` (space/←/→/`<`/`>`) + `KeyframeRegistry` jump-to-event. No on-screen transport exists today.
- [x] **4.2 — per-view header menus DONE.** New `src/ViewUIBarMenus.js`: a **declarative registry** (`VIEW_UIBAR_MENUS`) of what each view's CUIBar title menu contains, plus `registerViewMenuItem(viewId, slot, controller)` at each control's creation site and `populateViewUIBarMenu(view)` from `CNodeView.createViewHeader`. Everything is a MenuMirror twin, so there is no second flag, no second onChange and nothing extra serialized. Landed: **Main** (measurements/labels/features, FOV, Y-compress, Night Sky group), **Look** (the same three, all-tracks, north-up, Y-compress, Night Sky group, Video Overlay group: transparency/key colour/key tolerance/ground video), **Video** (zoom, rotation, video info, grid, annotations, EXIF, Adjustments group, Masking group).
  - **Order-independent by construction:** the registry is read when the header is built, and controls created later in the load (night sky, video) drop into their declared position when they appear (`placeInOrder`). Groups are pre-created hidden and revealed only when something lands in them, so a sitch with no night sky/video gets no empty headings.
  - `CUIBar` gained two matching fixes: "is this menu empty" now asks whether anything is *visible* (hidden groups no longer make an empty menu openable), and the dropdown is capped to the space below the bar with `overflow-y:auto` so a low-docked view's now-long menu cannot run off the bottom of the screen.
  - Guarded by `tests/ViewUIBarMenus.test.js` (registry shape, i18n coverage, and a static scan pairing every registry slot with a `registerViewMenuItem` call in `src/` — both directions) and `tests/MenuMirror.test.js` (18 cases against the real lil-gui). Verified live over MCP incl. two in-page sitch switches (perm sources survive; per-sitch ones rebuild).
  - Fixed on the way: `Controller.prototype.tooltip` never stored `_tooltip`, so BOTH mirroring paths were silently producing tooltip-less twins.
- [ ] **4.4** Remaining 4.2 candidates: atmosphere/effects on Main, lock-track and FOV/zoom on Look, a header menu for the second video view (`video2` — needs the registry keyed by view ROLE, not id), and per-view icon buttons (fullscreen/overlay toggles) alongside the menu.
- [x] **4.2b — mirroring promoted to a lil-gui extension, and `.listen()` made to mean the same thing everywhere.** Reported symptom: a header row and its Show-menu original disagreeing. Root cause was NOT the mirror — the fork replaced lil-gui's per-controller rAF with `CGuiMenuBar.updateListeners()`, which only walked the docked menu-bar SLOTS, so `.listen()` was a silent no-op in every other root (detached menus, mirrored popups, per-view headers). A control changed without going through a controller (sitch load, API, script) left those displays stale with no way back; the `activePersistentMenu`/`activeContextMenu` lines were an earlier ad-hoc patch of the same bug.
  - `src/GUIRootRegistry.js` — any non-slot root registers and gets the same once-a-frame listener pass. CUIBar registers its menus only while the bar is shown (no idle cost; a hidden menu catches up the frame it reappears, since lil-gui compares against `_listenPrevValue`).
  - Twins now inherit the source's `.listen()`, so a mirror self-heals from any bypass rather than only from changes that went through a controller.
  - Mirroring is now a chainable lil-gui extension rather than a helper you wrap expressions in: `control.shareAs(key)` / `gui.addMirror(key, opts)` / `control.mirrorTo(gui)` / `gui.mirrorFolderFrom(folder)`. All 33 call sites are plain chained calls now.
  - `CustomManagerMirror.mirrorGUIControls` delegates to `mirrorFolderFrom`, deleting ~190 lines of a second, drifted copy of "clone a controller" — that copy identified kinds by `constructor.name` (renamed by the production minifier, so colour pickers and sliders degraded in the shipped build only) and read tooltips from a field nothing wrote. Verified live: a mirrored View menu reproduces all 27 rows in order, with working sliders and side effects.
  - Tests: `tests/GUIRootRegistry.test.js` (new) plus MenuMirror cases for listen-inheritance and bypass repair.
