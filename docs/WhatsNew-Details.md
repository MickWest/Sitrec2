## Version 2.62.3 (2026-05-27)

### New Features
- **Sun Reflection slider on synthetic clouds** (Objects → *Clouds: \<name\>* → Properties): a new `sunReflection` slider is added to `CNodeSynthClouds` (`src/nodes/CNodeSynthClouds.js`), range 0–10000 in steps of 1 (meters), default 0 (no-op). The control sits in the Properties subfolder alongside Density/Opacity/Brightness, uses the new `synthClouds.sunReflection.label` i18n key (`src/i18n/en.js`), and persists via `serialize()` / `static deserialize()`. Implementation adds two `ShaderMaterial` uniforms — `reflectionPoint` (vec3) and `reflectionRadius` (float) — and a per-frame `preRender(view)` update. When `sunReflection > 0`, `Globals.sunLight` exists, and `this.localUp` is set, `preRender` looks up `NodeMan.get("lookCamera", false)` and computes the specular reflection point on the locally flat cloud plane through `this.group.position` with normal `localUp`: it mirrors the lookCamera position across that plane (`camMirror = camPos − planeNormal · 2h`, where `h = (camPos − planePoint) · planeNormal`), then traces a ray from `camMirror` in the already-normalized `sunDirection` until it intersects the plane (`t = −((camMirror − planePoint) · planeNormal) / (sunDir · planeNormal)`), and writes the resulting world-space point into `reflectionPoint`. If `sunDir · planeNormal ≤ 0.001` (sun at or below the cloud horizon), the effective radius is left at 0 so the shader noops. The fragment shader now computes `planeNormal = normalize(reflectionPoint − earthCenter)`, projects `vWorldPosition − reflectionPoint` onto the plane, takes its length `pdist`, and multiplies the diffuse-lit color (`texColor * color * lighting`, BEFORE `emissive` is added) by `1 + max(0, 1 − pdist / reflectionRadius)` — so brightness is +100% at the exact reflection point and decays linearly to +0% at `reflectionRadius`. The reflection point intentionally tracks the *look* camera only (not `view.camera`), so the glint stays anchored to what the look view is pointing at even when the same cloud layer is observed from `mainView`.

### Improvements
- **URL drag/drop and paste on the sitch browser** (`src/CSitchBrowser.js`, `src/DragDropHandler.js`): the sitch browser's overlay drop zone, previously file-only, now also accepts URLs. The drop-hint label changes from *Drop files to create a new sitch* to *Drop files or URLs to create a new sitch*. The internal/external drag filter is widened from `dataTransfer.types.includes("Files")` to a new `hasExternalDropData` helper that also matches `"text/uri-list"` and `"text/plain"`, applied to `dragenter`/`dragover`/`drop`. When the drop carries no files, the handler falls back to `DragDropHandler.getDroppedText(dataTransfer)` (extracts the first non-comment line of `text/uri-list`, falling back to `text/plain`, trimmed) and pushes the URL onto a new `DragDropHandler.pendingDropTexts` queue, parallel to the existing `pendingDropFiles` queue. The custom-sitch load is now shared via `_loadCustomSitchForQueuedDrops(queuedCount)`, called whenever at least one file *or* one URL was queued. `DragDropHandler.handleDrop` (the post-load processor) drains `pendingDropTexts` after `pendingDropFiles`, dispatching each via a new `handleDroppedText(text)` method. `handleDroppedText` consolidates the `http://`/`https://` discriminator that the old `else` branch of `onDrop` did inline: URLs go to `uploadURL(text, {persistDrop: true})`, anything else goes to `uploadText(text)`. The search box (`si` in `addSearchInput`) also gains a `paste` listener: pasted text starting with `http://` or `https://` is intercepted (preventDefault + stopPropagation), pushed onto `pendingDropTexts`, and triggers the same `_loadCustomSitchForQueuedDrops(1)` flow so a pasted URL behaves identically to a dragged one.
- **War.gov PR-coded Metabunk URLs resolve without fetching the thread** (`src/MetabunkThreadUtils.js`): `resolveMetabunkThreadVideoURL` now extracts a `PR-NNN` War.gov release code from the *thread URL itself* via `extractWarGovPRCode(threadURL)` before any HTTP traffic. If a code is found, it calls `getWarGovUFODvidsIdForPrCode(prCode, fetchImpl)` against the bundled `data/WARGOV/uap-data.csv` / `uap-release001.csv` index; on a hit it routes straight to `resolveDvidsVideoURL("https://www.dvidshub.net/video/<id>", fetchImpl)`, skipping the Metabunk thread fetch entirely. Failures in that fast path are swallowed and the function falls through to the existing thread-HTML scrape, so this is a pure optimization. Covered by a new `MetabunkThreadUtils.test.js` case ("resolves PR code from the thread URL before fetching Metabunk HTML") that asserts the thread URL is never fetched when the PR code resolves, using the `dow-uap-pr072-…14909` example URL.

## Version 2.62.2 (2026-05-27)

### Bug Fixes
- Fixed a double-unescape edge case in `decodeHTMLEntities` in `src/DVIDSUtils.js` and `src/MetabunkThreadUtils.js`. The previous sequential `.replace()` chain decoded `&amp;` first, so an already-encoded payload like `&amp;lt;` collapsed to `<` instead of `&lt;` because the substituted `&` was reconsidered as the start of the next entity. Rewrote both as a single-pass `String.replace` over `/&(amp|quot|#39|lt|gt);/g` backed by a `HTML_ENTITY_MAP` lookup, so each character is visited once and double-encoded input round-trips correctly. The existing 12 tests in `DVIDSUtils.test.js` and `MetabunkThreadUtils.test.js` still pass. Closes CodeQL alerts #48 and #49 (`js/double-escaping`).

### Security
- Hardened the Metabunk host check in `isIgnoredMetabunkMP4URL` (`src/MetabunkThreadUtils.js`). The previous `parsed.hostname.endsWith("metabunk.org")` test would also match attacker-controlled lookalike hostnames such as `evilmetabunk.org`; the check now requires either an exact host match or a true `.metabunk.org` subdomain before the `/styles/` path filter is applied. Defensive hardening — no known exploit path through real upstream thread content. Closes CodeQL alert #50 (`js/incomplete-url-substring-sanitization`). Alert #47 (`js/clear-text-storage-of-sensitive-data` for an API key stored in `localStorage` by `tools/airport-arrivals/index.html`) was dismissed as won't-fix: the standalone client-side tool stores the user's own ADS-B Exchange key with no backend, which is the canonical pattern.
- Upgraded `qs` to 6.15.2 in `package-lock.json` and `tools/SitrecBridge/package-lock.json` (transitive via `express` / `body-parser` and `webpack-dev-server → express@4`), closing Dependabot alerts #132 and #133 (DoS via `TypeError` in `qs.stringify` on `null`/`undefined` entries in comma-format arrays when `encodeValuesOnly` is set; medium severity). Pulled via `npm audit fix`.
- Upgraded `uuid` to 11.1.1 via a new `overrides: { "uuid": "^11.1.1" }` block in `package.json` (transitive via `sockjs → webpack-dev-server`), closing Dependabot alert #131 (missing buffer bounds check in v3/v5/v6 when a `buf` argument is supplied; medium severity). Our only caller is `sockjs` invoking `uuid.v4()` with no arguments, so the CVE is not reachable in practice, but the patched version ships anyway. The `npm audit fix` suggestion of downgrading `webpack-dev-server` 5.x to 1.16.5 was rejected. `npm audit` now reports 0 vulnerabilities in both lockfiles.
- Upgraded `tmp` to ≥ 0.2.6 in `apps/video-viewer/package-lock.json` (transitive via `electron-builder → app-builder-lib → @malept/flatpak-bundler → tmp-promise`), closing Dependabot alert #134 (path traversal via unsanitized `prefix`/`postfix`; high severity). Pulled via `npm audit fix`; `npm audit` now reports 0 vulnerabilities in the video-viewer lockfile.

## Version 2.62.1 (2026-05-27)

### Improvements
- **Render Source Video shortcut in Video Adjustments** (Video → Video Adjustments): a second `Render Source Video` button is added at the bottom of `addFiltersToVideoNode` in `src/nodes/CNodeVideoViewFilters.js`, bound to the same instance method as the existing button in Video → Video Render & Export — `CustomManager?.videoExportManager?.exportSourceVideo()`. Both buttons share the `videoExport.renderSource.label` / `videoExport.renderSource.tooltip` i18n keys, so future changes to the source-render flow or its translations apply to both. The button is styled light-green via the project's canonical `Controller.prototype.setLabelColor("#90EE90")` extension (`src/lil-gui-extras.js`), which injects a per-controller `<style>` block with `!important` rules — the only reliable way to override lil-gui's per-element `color: var(--text-color)` on a `<button>` (earlier inline `domElement.style.backgroundColor` / `style.color` writes silently lost to lil-gui's own CSS). A companion fix in the same change makes the green styling survive controller mirroring: `setLabelColor` now records `this._labelColor = color` after injecting its style block, and `mirrorController` in `src/CustomManagerMirror.js` replays `setLabelColor(controller._labelColor)` on the mirrored controller right after copying the tooltip. The standalone right-click Video Adjustments popup (and any other mirrored panel) now shows the same label colors as the source folder, which also restores colors that were silently dropping out of mirrored copies elsewhere in the codebase — the file-manager "Saving Disabled" warning, the PTZ angle indicators, the current-sub-sitch indicator, and any other `setLabelColor`-styled control.

### Bug Fixes
- **Blurry, overlapping, and z-fighting terrain tiles**: `QuadTreeMap.reconcileTextureCut` in `src/QuadTreeMap.js` is rewritten to maintain a single per-view rendered cut for texture tiles. The previous reconcile pass could reveal a deep ready branch and then have a shallower fallback parent suppress it again in the same pass, and partial descendants could render against a fallback parent — producing z-fighting and blurry fallback imagery, especially after zoom-in followed by zoom-out and after camera `goToPoint`. The new reconcile walks texture cuts top-down, marks fallback-owned branches for the pass, and tracks ready-vs-rendering tiles with `renderSuppressedLayers` on `QuadTreeMapTexture` so descendants can finish loading without drawing over fallback parents. Stale suppression is cleared when an active parent becomes a fallback again, merges only collapse immediate active children (not the deep subtree, which was over-flattening), and coverage-visible texture leaves are kept alive when strict OBB subdivision culling would otherwise reject them (`QuadTreeCullingBounds.js`). `CNodeCamera` now refreshes subdivision after `goToPoint` and fingerprints camera matrices after `matrixWorld` updates so the reconciler sees the post-move pose on the same tick. A new 276-line regression test `tests/QuadTreeMapReconcile.test.js` covers the reveal/suppress race, the merge-immediate-children rule, and the post-`goToPoint` refresh; the OBB helper import path is normalized for Jest/Webpack and Three is deduped via a `package.json` resolution so the test runs against the same Three instance as the app.

## Version 2.62.0 (2026-05-27)

### New Features
- **Orbit Image Set: Vertical FOV control** (File → Export → Orbit Image Set): added a `Use Current Camera FOV` checkbox (default on) and a `Vertical FOV (deg)` slider (range 0.1–120, default 30) in `src/ExportImageSet.js`. When the checkbox is off, the export locks the look camera's vertical FOV to the slider value once before the orbit loop (look-camera controllers are already disabled during export) and re-pins it inside `_applyPreviewCameraPose` so other nodes (match-video-aspect, fovOverride, etc.) can't nudge it mid-shot. Both `exportImageSet` and `exportImageSetFullscreen` honor the setting; the saved/restored `savedFov` snapshot is added to the existing snapshot/restore block.
- **Orbit Image Set: JPEG output** (File → Export → Orbit Image Set): new `Use PNGs` checkbox, default off. With it off, each shot is encoded as JPEG at quality 0.9 via the renamed `canvasToImageBlob` helper (formerly `canvasToPngBlob`); with it on, PNG is preserved. Filename extension switches with format (`.jpg` / `.png`). PNG encoding was the long tail of per-shot wall time; JPEG cuts encode time ~5–20× and file size ~10–15× at imperceptible loss on terrain/sky-dominated shots.
- **Orbit Image Set: Orbit Preview mode** (File → Export → Orbit Image Set): new `Orbit Preview` checkbox repurposes the main frame slider as an index into the precomputed orbit shot list (az_steps × el_steps × time_steps). `_enterPreview` snapshots camera pose/FOV, `Sit.frames`/`aFrame`/`bFrame`, `par.frame`, `Sit.startTime`, render hooks, controls, and the look-camera controllers (disables them like the export does); `_applyPreviewFrame` runs per tick via `Globals.orbitPreviewApply` (called from `updateFrame.js` after the slider sync) and moves the camera to the current shot's az/el at the current distance, shifting `GlobalDateTimeNode.startDate` at time-step boundaries. The frame slider tints green (`#1a5d2a` track, `#2ecc71` accent) to signal the mode. `preRenderFunction` re-applies the orbit pose just before each `lookView` render, fixing a two-position flicker when `fixedTarget` moved (CNodeCamera.update runs `altAdjust` and `applyGroundTrackSwitch` directly, bypassing the disabled controllers, between the per-tick update and the GL pipeline reading `camera.matrixWorld`). Orbit Distance and Vertical FOV update the preview live; `_buildShotList` is shared by preview and export so the geometry stays in lock-step. Clicking `Export Image Set` while preview is on auto-exits preview first so the export's own snapshot/restore captures a clean pre-export state. `_exitPreview` restores everything captured at enter time, including slider styling.
- **Video tonal adjustments: Shadows, Highlights, Dehaze** (Video → Video Adjustments): three new sliders in `src/nodes/CNodeVideoViewFilters.js`, range -100 to +100, default 0, with i18n keys `videoShadows`, `videoHighlights`, `videoDehaze`. Implemented as a per-pixel pass (`applyTonalAdjustmentsToImage` → `applyTonalAdjustmentToPixel`) inserted into `CNodeVideoView.getAdjustedVideoFrameSource` between Curves and Invert. Shadows lifts/crushes darker tones using a luma-based region weight centered at 0.1; Highlights does the same for brighter tones centered at 0.9; Dehaze adds a contrast-around-airlight (220) plus saturation pass when positive, or blends toward airlight with reduced saturation when negative. Result is cached per `(image, frame, shadows:highlights:dehaze)` key on `_tonalAdjustCanvas`. Reset button in Video Adjustments resets all three. The `applyByteInvertToImage` cache now also keys on a per-effect `sourceKey` so Invert correctly re-runs when the upstream chain changes.
- **Histogram tonal-loss readout** (Video → Video Adjustments → Histogram): the live RGB histogram view (`CNodeVideoHistogramView`) now overlays a tonal-resolution stats line — `Levels NN% | N.Nb | CXX | WX:1` — showing what fraction of distinct RGB input levels survive the current adjustment chain, the effective output bit depth, total collapsed inputs across RGB, and the worst many-to-one collapse for any output level. The text tints amber when any collapse is present. A transparent hover div over the readout exposes a tooltip explaining each value. Stats are computed in `calculateTonalLossStats` using per-channel `originalSeen`, `adjustedSeen`, and reverse-map bitmaps built during the histogram pass.
- **Lines of Sight: Current LOS toggle** (Show/Hide → Current LOS): new per-LOS-display checkbox (i18n key `showHiders.currentLOS`, tooltip "Show only the current frame's line of sight"). When on, `CNodeDisplayLOS` draws a single white `Line2` for just `par.frame`'s LOS into a dedicated `currentLOSGroup`, on top of the existing per-second LOS bundle. Endpoint math (including the clip-to-sea-level path for downward-pointing LOSes on large-tile sitches) is extracted into a shared `getLineEndpoints(f)` so `recalculate()` and `updateCurrentLOS(f)` share one implementation. `showCurrentLOS` is added to `simpleSerials` so the toggle survives serialization; a new `dispose()` cleans up the group, the `Line2`, and the `LineGeometry`.

### Improvements
- **Curves editor: easier to grab handles** (Video → Video Adjustments → Curves): point and curve hit radii in `CNodeVideoCurvesView` doubled — `HIT_RADIUS` 9 → 18 and `CURVE_HIT_RADIUS` 10 → 20 — so clicking near a control point or curve segment is far more forgiving without changing the visible curve.
- **View dragging: drag-off-top to close, any view commits its new position**: in `CNodeView.onViewDragEnd`, the early-return on `!this.dockable` is moved to AFTER the new position is committed via `setFromDiv(this.div)` and AFTER a top-edge close check — so any draggable view now persists its dragged position on release (previously only dockable views did), and dragging any view above `CLOSE_OFF_TOP_PX` (-5px) hides it via `setVisible(false)`.
- **Camera controls: symmetric vertical tilt clamp**: `CameraMapControls.rotateUp` in `src/js/CameraControls.js` now clamps the camera elevation symmetrically between -89° and +89° (constants `MIN_CAMERA_ELEVATION_DEGREES` / `MAX_CAMERA_ELEVATION_DEGREES`) by computing the target elevation, clamping it, and converting back to an angle delta. Replaces the old nadir-only guard, so the camera no longer pops past the zenith and the residual angle math no longer fires a tiny rotation when fully clamped.

### Bug Fixes
- **Histogram clip indicators on inverted video**: `CNodeVideoView.calculateClippingDistribution` now feeds the "original" comparison value through `getClipComparisonValue(value, invertActive)`, which mirrors via `255 - value` when the Invert filter is on. Previously the shadow/highlight clip masks compared the inverted output against the un-inverted source and reported spurious clipping.
- **Saved GUI flags loading as off**: `CNodeGUIFlag` now coerces incoming values through `normalizeGUIFlagValue` (true / 1 / "1" / "true" → on) on construction, on user change, and during `modDeserialize`, so flags persisted as numeric or string-truthy in saved sitches restore correctly across the many filters that use it.

## Version 2.61.2 (2026-05-26)

### Improvements
- **Invert switched from CSS `invert()` slider to true byte-invert checkbox**: `videoInvert` in `addFiltersToVideoNode` (`src/nodes/CNodeVideoViewFilters.js`) is now a `CNodeGUIFlag` (boolean, default `false`, tip "Invert colors with exact 255 - byte mapping"), was a 0-1 `CNodeGUIValue`. The CSS `filter: invert(x)` path is removed from `CNodeVideoView.getAdjustedVideoFrameSource` (`src/nodes/CNodeVideoView.js`) and from `getVideoEffectsFilterString` in `CMotionAnalysis.js`. A new `applyByteInvertToImage(image, videoView, frame)` in `CNodeVideoViewFilters.js` does the inversion in an image-data pass — `data[i] = 255 - data[i]` per RGB channel, alpha untouched — onto a per-`CNodeVideoView` cached canvas (`_invertCanvas`/`_invertCtx`, allocated `willReadFrequently: true`, re-allocated only on size change) keyed on `(image, frame)` so repeat reads of the same frame return the cached canvas. Called from `getAdjustedVideoFrameSource` right after `applyCurvesToImage` and before the convolution/blur stages, so invert composes inside the rest of the pixel-data pipeline rather than being smeared onto the final CSS render. The CSS `invert(x)` blend isn't a real photographic negative at intermediate values; the byte-invert pass is.
- **Removed *Greyscale* control**: the `videoGreyscale` `CNodeGUIValue` is no longer created in `addFiltersToVideoNode`, removed from `CNodeVideoView.optionalInputs`, removed from the live `filter` string in `getAdjustedVideoFrameSource`, and removed from `getVideoEffectsFilterString` in `CMotionAnalysis.js` (so motion-analysis exports also drop the greyscale step). The corresponding `getFilterNodes` / `attachInputsToVideoNode` registrations are gone. The `videoGreyscale` i18n key in `src/i18n/en.js` is left in place (harmless — nothing reads it). *Saturate* at 0 produces the same visual result.
- **Sharpen Amount = 0 is identity and sharpen no longer ringed the frame in black** (`applyConvolution` in `CNodeVideoViewFilters.js`). The sharpen kernel was `[0, -A, 0; -A, 5A, -A; 0, -A, 0]` which sums to `A` — so at `A=0` the kernel is all-zero and the convolution wrote zero to every interior pixel (the resulting black image was then *not* merged back because of the "if all-zero, skip" guard, so what the user actually saw was a no-op… but with `A=1` the original output was already a much stronger sharpen than visually expected and lerping between them was inconsistent). New kernel `[0, -A, 0; -A, 1+4A, -A; 0, -A, 0]` sums to `1` regardless of `A`, so `A=0` is the identity kernel (pass-through) and `A=1` matches the previous "full-strength" sharpen. Two related fixes in the same function: (a) the inner colour loop is now `c < 3` (alpha is no longer convolved at all, instead of being convolved then copied back), and (b) the output buffer is allocated as `new Uint8ClampedArray(data)` (a copy of the source) instead of `new Uint8ClampedArray(data.length)` (zero-filled), so the un-touched border ring (`y=0`, `y=h-1`, `x=0`, `x=w-1`) carries the original pixels instead of being black. The post-loop "merge non-zero output back into data" hack is gone — the function now calls `ctx.putImageData(new ImageData(output, w, h), 0, 0)` directly.
- **Video Curves editor: endpoints unpinned from x=0/x=255** (`CNodeVideoCurvesView.js`). Previously `normalizePoints` pad-inserted `{x:0,y:0}` and `{x:255,y:1}` whenever those exact x values weren't present, then *forced* `deduped[0].x = 0` and `deduped[deduped.length-1].x = 255` after sort/dedupe — so any attempt to drag an endpoint inward got rewritten back to the edge on the next normalize pass, and the endpoint check (`isEndpointIndex`) was "x is literally 0 or 255". Now: pad-insert only when there are 0 or 1 points (legal degenerate cases) — a single point at x<128 pads `{255,1}` and a single point at x≥128 pads `{0,0}`. The forced-x rewrite is gone. `endpointRole(index)` identifies start/end by position-in-sorted-order (`sorted[0]`, `sorted[len-1]`), not by exact x; `isEndpointIndex` delegates to that. In `setPointFromLocal`, the start endpoint is constrained to `x ≤ neighbour-1` and the end endpoint to `x ≥ neighbour+1` (keeping monotonicity) but otherwise both can move freely in x — matching Photoshop Curves where pulling the left endpoint right clips the input shadows. Independently, the `rectContainsPoint(graphRect, …)` early-return in `onMouseDown` is now only gated on the *new-point* path; selecting/dragging an *existing* point is no longer rejected when the pointer wanders outside the graph rect, so a drag that takes a control point off the visible area no longer detaches mid-drag.
- **Reset Video Adjustments updates the displayed controls** (`addFiltersToVideoNode.reset.resetFilters`). The whole reset path was rewritten from direct `videoNode.inputs.<name>.value = …` writes to a new `resetInput(name, value)` helper that prefers `node.setValue(value)`, falls back to `node.guiEntry.setValue(value)`, and only writes `node.value = value` as a last resort. The previous direct-`.value` writes bypassed lil-gui's onChange dispatch, so the slider/checkbox/dropdown UI stayed at the pre-reset position even though the underlying value was new. As part of the same pass: the Levels reset now delegates to `videoNode.levelsView?.resetLevels()` (which is the editor's own reset path — handles the five handle positions correctly) with a fall-through to individual `resetInput` writes only if no Levels editor exists, and Curves reset delegates to `videoNode.curvesView?.resetCurve()`. The Convolution Filter dropdown also explicitly calls `convolutionFilterDropdown.setValue("none")` (was only updating `filterOptions.convolutionFilterValue`, which didn't refresh the dropdown widget). Removed the now-redundant per-input `if (videoNode.inputs.<name>)` guards — `resetInput` no-ops on missing inputs. `invert` resets to `false` (matching its new flag type) and the `greyscale` reset line is gone.
- **Empty-video Video sitch keeps the drop-zone hint pinned** (`src/DragDropHandler.js`, `src/sitch/SitVideo.js`, `src/nodes/CNodeVideoView.js`, `src/nodes/CNodeVideoWebCodecView.js`). `CDragDropHandler.addDropArea` now accepts an options object; passing `{keepTextVisibleUntilMedia: true}` sets the `keepDropZoneTextVisible` flag, which (a) starts the drop-zone visible instead of opacity-0, (b) routes `hideDropZone()` through a new `showPassiveDropZoneText()` (visible, transparent background, no pointer events, full opacity) instead of hiding the element entirely, and (c) wires a one-shot `ensureMediaImportListener()` that listens for `videoImportStarted` and `videoLoaded` events on `EventManager` and clears the persistent text the first time either fires. `onDrop` now calls `clearPersistentDropZoneText()` (which flips the flag off then calls `hideDropZone()`), so the first real drop ends the persistent state too. `CNodeVideoView.uploadFile` dispatches `videoImportStarted` at the top of the import path; `CNodeVideoWebCodecView._doUploadFile` dispatches the same event for the WebCodec path. `SitVideo.setup()` passes `{keepTextVisibleUntilMedia: this.file === ""}` — so the Video sitch *with* a preset video keeps the old fade-out behaviour, and the Video sitch *without* one keeps the hint until the user actually drops something.
- **`SitVideo` no longer force-docks the Video menu into the right sidebar**: the `addMenuToRightSidebar(videoMenu); videoMenu.mode = "SIDEBAR_RIGHT"; … applyModeStyles(videoMenu)` block in `SitVideo.setup` is removed (and the now-unused `Globals` and `addMenuToRightSidebar` imports cleaned up). The Video menu opens as a normal floating menu now, and the user can dock it themselves via the dockable-views system added in 2.61.0 if they want it pinned.

## Version 2.61.1 (2026-05-26)

### Improvements
- **Dockable text views**: extends the 2.61.0 dockable-floating-views system to text panels. `CNodeNotes` (`src/nodes/CNodeNotes.js`) now passes `v.dockable = true` (it was previously locked out because the base view sets `dockable` from `draggable`, and Notes forces `draggable = false`), and `CNodeViewText` (`src/nodes/CNodeViewText.js`) defaults `v.dockable = v.dockable ?? wasDraggable` so any draggable text view inherits dock support. Both classes now also wire an `onDragEnd` callback into their drag setup (`data.viewInstance?.onViewDragEnd?.(event, data)`), which is what runs the edge-proximity dock decision in `CNodeView`; without that wiring the dock pipeline never fired for text views in 2.61.0. The per-tick `onDrag` handlers in both classes early-return when `view.dockedSidebar` is set, so the docked layout in the sidebar isn't fought by the floating drag-position math (`CNodeViewText` additionally now calls `view.setFromDiv(view.div)` on each drag tick to keep its floating rect in sync, matching what `CNodeNotes` already did).
- **Docked text scales down to fit the sidebar**: `CNodeView` gains a `dockedTextScale` field (set to `0.8` by default on `CNodeNotes` and on `CNodeViewText` via `v.dockedTextScale = v.dockedTextScale ?? 0.8` before `super(v)`). New `applyDockedTextScale()` / `restoreDockedTextScale()` methods walk `this.div.querySelectorAll("*")`, snapshot each element's inline `style.fontSize` into `dockedTextOriginalFontSizes` (a `Map`), and rewrite each element's `style.fontSize` to `getComputedStyle(el).fontSize * dockedTextScale` in pixels. `applyDockedTextScale()` is called from `updateDockedWH()` (so the scale is applied whenever the sidebar layout updates), and `restoreDockedTextScale()` is called from `undockFromSidebar()` to put the original inline font sizes back. The apply path no-ops if there is no scale set or if a scale snapshot is already active, so non-text views are unaffected.
- **Dock state persists across sitch save/load**: `CNodeView.modSerialize` now writes `dockedSidebar: "left" | "right"` when the view is currently docked, and `modDeserialize` restores it. The restore path is order-sensitive: it reads the saved value into `restoredDockedSidebar`, calls `undockFromSidebar()` if the view is somehow already docked (defensive), applies the rest of the simple-serial deserialization, then calls `dockToSidebar(restoredDockedSidebar)` before the `setVisible(v.visible)` toggle at the bottom — the existing `this.visible = !visible; setVisible(visible)` pattern is preserved so the visibility-change side-effects still fire. Saves from 2.61.0 (no `dockedSidebar` field) load unchanged.

## Version 2.61.0 (2026-05-26)

### New Features

Pixel mapping moves into `buildLevelsLUT`/`applyLevelsToImage` (`CNodeVideoViewFilters.js`), which generate a single 256-entry LUT per change of `(inputBlack, inputWhite, midpoint, outputBlack, outputWhite)` — keyed via `_levelsLastKey` — applying `out = outBlack + ((clamp(in, inBlack, inWhite) − inBlack)/(inWhite − inBlack))^(1/midpoint) × (outWhite − outBlack)`. The Levels editor and the existing Curves editor are now both opened/closed by the same Video Adjustments visibility handler (`updateVideoAdjustmentHelperVisibility` fans out to `updateLevelsVisibility` and `updateCurvesVisibility`); when both are visible at once and would overlap, `moveEditorTowardCenterIfOverlapping` nudges the newly-opened panel inward so the two never sit on top of each other.
- **Dockable floating views**: `CNodeView` (`src/nodes/CNodeView.js`) gains a `dockable` flag (defaults to `draggable`) and a complete dock/undock subsystem. On drag end, if the pointer is within `DOCK_EDGE_PX` (36 px) of the left/right window edge — or already inside the corresponding sidebar's `getBoundingClientRect()` — the view's `<div>` is re-parented into the left or right sidebar (`getLeftSidebar()`/`getRightSidebar()` from `PageStructure.js`), its absolute positioning is swapped for relative + margin (`DOCK_MARGIN_PX` = 8), resize handles are hidden, and its size is recomputed by `updateDockedWH()` to fit the sidebar's inner box while preserving the floating aspect ratio (cached at dock time as `dockedAspectRatio`). The floating rect (`leftPx/topPx/widthPx/heightPx`) is captured into `floatingRectBeforeDock` before docking and restored on undock — including a `requestAnimationFrame`-deferred pixel-size restore so the view doesn't shrink to a degenerate size during the parent swap. Dragging a docked view back out of the sidebar undocks it at the pointer's location (centred horizontally on the cursor, 16 px above the cursor vertically), clamped inside the floating parent's container. The sidebar containing a docked view auto-shows on dock (`showLeftSidebar`/`showRightSidebar`) and auto-hides when its last visible child is removed (`hideSidebarIfEmpty` — invoked on undock, on `setVisible(false)`, and on `dispose`). The drag pipeline gains `onDragStart`/`onDragEnd` callbacks so the dock decision runs only on drag release; while a view is docked, the per-tick `onDrag` returns early and `updateWH` short-circuits to `updateDockedWH` so the normal fractional-positioning path can't fight the docked layout.

## Version 2.58.0 (2026-05-24)

### New Features
- **Physically based aerial perspective** (Effects → Atmosphere): the look view now composites distant geometry as `scene * T + sky_ray_color * (1 - T)`, where `T` is per-ray transmittance through an exponential atmosphere and `sky_ray_color` is the same per-ray sky gradient that paints the background. Distant buildings and terrain converge toward the color of the sky directly behind them instead of a fixed grey fog tint, so a city at the horizon under a yellow sunset goes yellow, under a blue overhead it goes blue. The *Atmo Visibility* slider is now mapped to physical extinction via Koschmieder's formula (`beta = 3.912 / visibility_meters`), and a normalized ray-distance prepass replaces hardware perspective depth so Earth-scale far planes do not collapse the precision available for haze integration. Surface-level, high-altitude, and near-space / satellite views all use the same height-integrated optical path through an exponential atmosphere with Rayleigh + aerosol scale-height sampling and a tangent / limb haze boost so long horizontal sightlines from space accumulate the dense lower atmosphere without an extra pass, while vertical-up sightlines correctly thin out. A continuous angle weight replaces the prior hard `slantViewT` threshold near 364,354 ft so angled-down high-altitude views no longer pop. An analytic Earth-surface/horizon air-mass fallback covers shallow sightlines into 3D Tiles where the lightweight depth prepass under-reports custom-positioned tile geometry. The feature is gated to lookView + Atmosphere + (*Horizon Haze* or *Sky Gradient*) and stays a no-op for IR/XR/legacy day-sky paths; the shader and distance render target are released when disabled. See `docs/AtmosphericAerialPerspective.md` for the full physical basis, controls, and limits.
- **Atmosphere horizon haze gradient** (Effects → Atmosphere): independent per-ray horizon haze gradient rendered in `CNodeView3D` and driven by the existing `CNodeSunlight.calculateHazeColors()` solar geometry — distinct from the legacy uniform-fog horizon and used as the sky-side input to the new aerial-perspective composite above.
