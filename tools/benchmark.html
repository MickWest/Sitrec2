    Recommendation method & limitations
    This is a synthetic two-view terrain workload, not a replay of a saved Sitrec scene. It includes textured heightmap displacement, tile skirts at 10% of tile width, logarithmic depth, separate surface/skirt draws, an offscreen render target, optional MSAA resolve and a display pass. The shader and scene are self-contained, not Sitrec’s production renderer.
    Render scale, MSAA, grid density, draw-call partitioning and overdraw are varied independently. Every actual Sitrec preset is then tested. A custom combination is selected from the isolated sweeps and tested together; a suggestion is only marked validated if that combined run meets the target. Heuristic headroom uses the larger of GPU p95 and CPU submission p95, not their sum. Presentation pacing is checked separately. Quick results have fewer samples.
    Maximum Details is a geographic zoom cap, not a triangle count. Draw/tile pressure can reveal sensitivity, but cannot calibrate that cap without real map sources. The recommendation leaves its preset default unchanged. Video-sized uploads and declared codec support do not measure decode speed; the video limit also remains a preset default. WebGL cannot report total or free VRAM. Estimated allocations below cover this test only. Browser-reported RAM and CPU concurrency can be rounded or reduced.
    GPU time uses asynchronous timer queries when available. CPU submission time is not GPU completion time. Frame rate depends on display cadence and scheduling. A hidden tab, resized window, lost graphics context or changed display scale interrupts the run. Close other demanding applications and keep the tab visible for repeatable results. Workloads are bounded to 8.3 million total pixels and approximately 512 MiB of owned rendering allocations; skipped cases above these bounds are not hardware failures.
    Reference APIs: GPU timing · GPU identity · Memory exposure · CPU concurrency.
    Troubleshoot unexpectedly poor performance
    • Compare the reported WebGL GPU with the card you expect. On Windows, choose High performance for the browser in Settings → System → Display → Graphics, restart the browser and rerun. This page requests high performance, but the browser and OS decide which adapter is used.
    • Check chrome://gpu or edge://gpu for the renderer and WebGL acceleration status. “Hardware accelerated” does not distinguish integrated from dedicated graphics. A software renderer can be a major bottleneck.
    • A high device pixel ratio can multiply pixel cost: 2× pixel ratio draws four times as many pixels. Reduce Render Scale first if the scale sweep shows a strong improvement.
    • Compare a plugged-in run with a battery run. Browser power-saving, other GPU workloads, screen recording, heat and driver problems can affect results. Rerun before making hardware conclusions.
    • If this benchmark is smooth but a particular sitch is slow, include its debug log, preset, window size, visible views, enabled effects and reproduction steps with this report. Video, downloads, scene logic and real 3D tile content can dominate that scene.
