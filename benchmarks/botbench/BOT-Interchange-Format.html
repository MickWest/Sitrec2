BOT Interchange Format

A CSV interchange for bearings-only tracking problems, so algorithms written outside Sitrec can be run on the same scenarios and scored against the same ground truth. Specification v1.0.

The problem it carries

A bearings-only sensor measures direction, never distance. Every sightline is consistent with a target anywhere along it — and that does not improve with more sightlines. For a target free to manoeuvre, some range profile reproduces any set of bearings exactly, at any sensor geometry.

Range becomes recoverable only once you impose dynamics on the target: a constant-velocity model, a physical one, or a smoothness prior. Which geometries then work depends on how much freedom that model leaves. The classic condition is that the sensor must out-manoeuvre the target model — a constant-velocity sensor cannot resolve a constant-velocity target — so on this benchmark's straight-platform cells the CV and Kalman fits land on the sensor every time: median relative separation 1.00, fail rate 1.00.

The same cells are untroubled by a rigid model. A fixed-point fit holds 0.08–0.09 relative separation there and never collapses, because a stationary target is over-determined by a straight baseline. "Observable" is therefore a property of the pairing — geometry and model together — and never of the geometry alone.

The four forms

Each scenario is four files. The first two are the challenge; the last two are the answer key, written to a separate directory so a sealed set can ship by handing over one folder.

input.csv

One row per frame, per track. All coordinates in metres, ENU.

ColumnReqMeaning
TrackIDyesJoin key across all four files.
TrackSourceyesFree-text provenance label. Not a sensor key — one sensor per track in v1.0.
TimeyesSeconds from epochISO.
Validyes0/1. A zero keeps the row — target out of frame, occluded, dropout. Deleting rows breaks the uniform time grid.
SensorPosE/N/UyesSensor position.
LosE/N/UyesSightline unit vector. Consumers may renormalise.
LosSigmaDegcolPer-axis white 1σ in the pan/tilt tangent plane; total angular RMS is σ√2. Blank for correlated error models, which have no white σ — read losError in scenario.json for the model and its scale before weighting anything by this column.
MinRangecolMetres. The column is always present, but blank means unconstrained and every scenario in the current release ships blank — the generator asserts no range bounds. Impose your own floor: without one the solution that collapses onto the sensor is formally optimal, which is exactly the trap the straight-platform scenario sets.
MaxRangecolMetres; blank if unconstrained. Also blank throughout the current release.

truth.csv

Two shapes. Finite targets carry positions; effectively-infinite ones (a star, a planet) carry bearings, because there is no position to recover.

TrackID,Time,TruthPosE,TruthPosN,TruthPosU,TruthVelE,TruthVelN,TruthVelU
TrackID,Time,TruthDirE,TruthDirN,TruthDirU

Velocity is derived by central difference, and truth.json says so — the balloon and bird truths come out of a numerical integration with no analytic velocity.

scenario.json & truth.json

scenario.json carries the frame, datum, timing, declared sensor error, an analyst-available wind estimate, and integrity digests. truth.json carries what a table of positions cannot: object class, event markers, realised noise statistics, the provenance needed to regenerate the scenario, and the degenerate-cell gate. That gate is three fields rather than one flag, because a single boolean conflated three unrelated claims:

"geometry": {
  "rangeDefined":               false,               // structural
  "cvConditioningApplicable":   false,               // gate before stratifying
  "cvConditioningBucket":       null,                // measured, or null
  "observabilityBasis":         "constant-velocity",
  "cvDesignLog10RcondObserved": -3.14,               // raw, no verdict attached
  "designIntent":               "no-finite-range"    // editorial
}

rangeDefined is derived from the truth kind: a target at effective infinity has no range to recover, which is categorically different from a range that exists but is badly conditioned. cvConditioningBucket is measured from the constant-velocity design matrix and says nothing about whether CV describes the target — a rising balloon in shear can be well-conditioned under CV and still badly modelled by it. designIntent is why the cell is in the set at all.

Where there is no range, there is no conditioning verdict: cvConditioningBucket is null and cvConditioningApplicable is false. Gate on that before stratifying. A direction-truth cell's sightlines are near-singular because the target is at infinity, not because the geometry is weak, so binning it as degenerate would file it alongside the straight-platform cells and undo the whole point of splitting the gate up. The raw rcond still ships — it is a real measurement of the sightline series — but carries no verdict.

The three can disagree, and that is the point of separating them. In the shipped set both members of the anomaly pair carry designIntent: "weak-geometry", yet one measures well-posed and the other marginal — same sensor path, different target motion. Stratify on the measurement; read the intent as a note from the author.

"frame": {
  "type": "ENU",
  "originLLA": [35, -125, 0],
  "ellipsoid": "WGS84",
  "surfaceModel": "flat-plane",
  "directionBasis": "originLLA"
}

Reading the frame

Two properties of the frame are invisible in the CSV and will silently change your answer if you assume the other one.

surfaceModel

flat-plane means truth sits on a flat plane and geodetic altitude equals the U coordinate directly. A wgs84-tangent set would need alt = U − (E²+N²)/2R — about 2 m at 5 km, 240 m at 55 km. Pure sightline fits do not care; anything altitude-coupled does.

directionBasis

The whole scene is one tangent frame anchored at originLLA, and every direction is expressed in the ENU basis at that origin — not the sensor's own local basis. The two diverge as the sensor moves away from the origin, by roughly d / R_earth. Compute ephemerides at originLLA.

Using it

# development set — descriptive filenames, truth alongside
npm run bench-bot-interchange

# sealed release — opaque ids, parameters drawn from a withheld salt
BOTBENCH_OPAQUE=1 BOTBENCH_SEAL_SALT=$(openssl rand -hex 32) \
  npm run bench-bot-interchange

The development set names files after their setup (straight-70ms-3000m_r5km_15s-10fps_partyneutral-500m…) and ships truth next to the challenge. That is what you want while building a reader. Those names are of course total truth leakage, which is the point of the other mode.

A sealed release splits into challenge/ and answers/, permutes ids under the salt, and — critically — draws the scenario parameters from the salt too. Without that last part the set is reproducible straight from the public templates in this repo, and the ids are exactly re-identifiable. The builder fails closed if no salt is given, and stamps NOT SAFE TO PUBLISH into any release built with hardening off.

Sealed hardening also withholds noiseless members and truth-sharing duplicates, replaces sensor paths that reveal the target's position, and measures both known extraction attacks at build time — re-drawing any geometry that fails. Publish the manifest digest up front; release the salt at scoring.

Known issues

No scoring specification open

The file formats are perhaps a fifth of this. Without one defined metric, a stratification rule for degenerate geometry, and a credit rule for abstention, two teams' numbers will not be comparable. output.csv is specified below but nothing writes or reads it yet.

TrackID,AlgorithmID,Time,Status,EstPosE/N/U,
  Kind,DirE/N/U,EstVelE/N/U,CovEE,CovNN,CovUU,CovEN,CovEU,CovNU

Status is ok / abstain / failed. The distinction is not pedantry: counting collapsed runs as successes rather than non-detections inflated one measured anomaly-detection AUC from 0.55 to 0.74.

Covariance is optional, and mostly absent known

None of Sitrec's eight solvers emits a position covariance. The Kalman path computes a full 6×6 internally and discards it. Blank means not reported; a scorer should rank accuracy for everyone and calibration only over the subset that supplies one.

Flat Earth known

Every scenario is flat-plane. The curved-surface variant is specified but not generated, so altitude-coupled results at long range are idealised.

designIntent is editorial, and disagrees with the measurement open

The intent labels are hand-set per scenario and have not been reconciled against the measured conditioning. Both anomaly-pair members are labelled weak-geometry; one measures well-posed. A scorer should stratify on cvConditioningBucket or on the raw cvDesignLog10RcondObserved — bucket thresholds come from measured collapse rates of 84% / 8% / 0% around log₁₀ rcond −3 / −2 / −1.

No field here claims observability in the abstract, because per the diagram above no set of bearings has it. On straight-platform cells the CV and Kalman fits fail at a rate of 1.00 while a fixed-point fit succeeds on every one at 0.08–0.09 relative separation, so a solver imposing stricter dynamics can and does recover range where the CV bucket reads degenerate.

Matched pairs remain linkable known

A matched pair shares its sensor trajectory by construction, so anyone can group shipped files by their SensorPos columns. For an anomaly/control pair that reveals one of the two is anomalous. The manifest publishes the grouping rather than implying it is hidden; a release that must not reveal pairing should ship one member of each.

Metadata fingerprinting against a public candidate list known

Ids are salt-permuted and rows id-sorted, so the mapping is not recoverable from order. It can still be narrowed by content when the candidate list is public source. A release that must resist that should draw from the full block matrix under a withheld seed.

Celestial truth is ephemeris-derivable known

A direction-truth scenario's answer follows from the published site and epoch plus any ephemeris. That is the intended solution path rather than a leak, but an entrant can score it without doing any tracking work.
